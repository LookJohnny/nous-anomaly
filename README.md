# nous-anomaly

**在大模型的内部激活上做异常检测：模型"状态不对"时，能不能不靠标注就发现？**

这个项目读取开源大模型每一层的内部激活，在上面训练两类检测器，并在同一批数据上正面比较：

- **单类异常检测器**：只见过"正常"对话的激活，偏离就报警。不需要任何风险样本。
- **有监督线性探针**：用标注过的风险样本训练，作为参照上限。

它是 [Nous Agent Safety](https://github.com/LookJohnny/nous-agent-safety) 的研究组件，对应其中"读取模型内部状态来监测风险"的方向。

> 状态：研究原型。目前只在一个模型（Qwen3-4B）的验证集上跑过三轮，测试集没有开封。所有标签来自 LLM 评分者，没有人工校准。

## 第一轮结果

模型 Qwen3-4B-Instruct-2507，4160 条中文对话记录，验证集，2026-11-18。数字是 AUROC（0.5 相当于随机猜）。

**结论：纯单类异常检测能发现情绪语气的变化，但发现不了敌意和附和。**

| 要检测的概念 | 单类检测器（没见过任何阳性样本） | 有监督线性探针 | 文本分类器 |
|---|---|---|---|
| 愤怒 / 喜悦 / 悲伤的语气 | **0.99** | 1.00 | 1.00 |
| 用户困扰（含明显关键词） | 0.67–0.80 | 0.997 | 0.994 |
| 用户困扰（去掉关键词） | 0.44–0.65 | 未测 | 未测 |
| 模型对用户的敌意 | 多数设置 0.43–0.77 | 0.94–0.97 | 0.94 |
| 附和（顺着用户的错误说法） | 0.32–0.53 | 0.87 | 0.71 |

怎么读这张表：

1. **情绪语气在中层最容易被发现。** 单类检测器在模型深度一半的位置（36 层中的第 18 层）达到 0.99，往浅层和深层都下降。不过这批数据里，带情绪的回复有一句明确的情绪开头，文本分类器也是 1.00。所以这一行只说明"语气明显变了能被发现"。
2. **敌意和附和不是离群点。** 敌意回复在激活空间里并不比正常回复离得更远。附和回复甚至比正常回复更"典型"，分数低于 0.5。只用同一数据集的正常样本来拟合，也没有改善。
3. **原因是高维稀释。** 风险信号只是少数几个方向上的偏移，淹没在其余两千多维的正常波动里。单类检测器不知道该看哪个方向。
4. **有监督探针有效。** 同一批激活上，线性探针检测敌意达到 0.94–0.97。在附和上，它比只看文字的分类器高 0.16，而且在模型开口之前就能读出来。
5. **"去内容"处理在真实数据上几乎没有额外收益。** 它和普通 Mahalanobis 的差别在 0.01 以内。换话题造成的误报本来就不高：没见过的话题上，正常对话的误报率是 3–11%，目标值是 5%。

这对方向的含义：要检测敌意、附和这类风险，仍然需要标注或对比数据来指明方向。纯单类检测可以留作"语气明显异常"的兜底信号。

### 读结果时要注意

- **验证集很小。** 敌意只有 12 个阳性样本，所有数字都是探索性的。
- **敌意一行的上限不可靠。** 个别设置能到 0.87，但那是 60 个设置里的最大值，不能当作结果。
- **有一次偏离预定流程。** 探索"按数据来源单独拟合"时，去关键词的困扰数据用了划给测试集的那部分，没有经过冻结。那一行只能算探索性数字。其余数据集的测试集没有开封。
- **只有一个模型、一种语言。** Qwen3-4B，中文。

原始数字在 [`results/`](results/)，只含汇总指标，不含对话原文。

## 第二轮结果：每个概念给几个样例

第一轮说明"零样例"不行。第二轮改成：正常语料提供几何结构（标准化、白化），每个概念只给 k 个阳性样例来定方向（`FewShotDirection`）。
同一批 Qwen3-4B 激活，验证集，每个 k 重复抽样 20 次取平均。层和读数方式事先固定，没有按标签挑选。

| 概念 | 读数位置 | k=1 | k=5 | k=20 | 全部样例 | 同样 5 个样例的文本分类器 |
|---|---|---|---|---|---|---|
| 敌意 | 回复均值，第 18 层 | 0.84 | 0.89 | 0.89 | 0.90 | 0.88 |
| 敌意 | **回复之前**，第 27 层 | 0.85 | 0.89 | 0.89 | 0.88 | 不适用（还没有文字） |
| 用户困扰 | 用户消息均值，第 18 层 | 0.96 | 0.99 | 0.99 | 0.99 | 0.99 |
| 愤怒 / 喜悦 / 悲伤 | 回复均值，第 18 层 | 0.92–1.00 | 0.99–1.00 | 1.00 | 1.00 | 1.00 |
| 附和 | 回复均值，第 18 层 | 0.55 | 0.61 | 0.67 | 0.75 | 0.58 |
| 附和 | **回复之前**，第 27 层 | 0.57 | 0.67 | 0.76 | 0.80 | 不适用 |

怎么读这张表：

1. **几个样例就够定方向。** 敌意从零样例时的接近随机，升到 1 个样例 0.84、5 个样例 0.89。用户困扰 1 个样例就有 0.96。
2. **回复写完之后，激活并不比文字更准。** 给同样 5 个样例，文本分类器在敌意上是 0.88，样例更多时还略高（全部样例 0.94 对 0.90）。
3. **激活的价值在"提前"和"难例"。** 模型开口之前，文字还不存在，激活已经能给出 0.85–0.89 的敌意预警。附和这种文字上看不出来的概念，激活在回复之前达到 0.80，文本分类器用全部样例也只有 0.71。
4. **附和仍然是难例。** 它需要上百个样例才到 0.80，离可用还有距离。
5. **一个合理性检查。** 情绪数据在"回复之前"的读数是 0.50。这批数据里情绪只出现在回复中，提示完全相同，所以回复之前不可能读得出来。结果符合预期。

和有监督逻辑回归探针相比，少样例方向在样例很少时相当（敌意 k=5：0.89 对 0.92），样例多时略低（0.90 对 0.95）。完整曲线在 [`results/fewshot_val_qwen3-4b.json`](results/fewshot_val_qwen3-4b.json)。

这一轮同样是探索性的：验证集的敌意只有 12 个阳性样本，标签没有人工校准。

## 第三轮结果：不用真实样例、逐 token 读数、更大的正常语料

这一轮让模型自己写数据（`generate.py`），然后重新提取了全部 12159 条记录的激活。

- **正常语料**：4999 条新对话，中英文各半，25 个主题 × 10 种提问类型，模型在没有系统提示的情况下作答。回复位置的正常样本从 1045 条增加到 4924 条。
- **对比样例**：五个概念各 300 对。每一对是同一段对话的两条回复：模型自己的回复，和按一句话定义"刻意表现出该概念"写出的回复。读激活时用的是原始提示，那条指令不在其中。

### 1. 只用合成样例定方向，在真实数据上测

方向完全来自合成的成对回复，没有用任何一条真实的阳性样例。验证集，第 18 层。

| 概念（真实数据） | 回复均值 | 回复前 16 个 token | 同样合成样例训练的文本分类器 | 对照：5 个真实样例（回复均值） |
|---|---|---|---|---|
| 敌意 | 0.84 | **0.96** | 0.84 | 0.92 |
| 愤怒 | 1.00 | 1.00 | 0.78 | 1.00 |
| 喜悦 | 0.98 | 0.90 | 0.74 | 1.00 |
| 悲伤 | 1.00 | 0.84 | 0.93 | 1.00 |
| 附和 | 0.53 | 0.58 | 0.68 | 0.64 |

- **敌意和三种情绪成立。** 一句话定义加上模型自己写的样例，就能检出真实的敌意回复。只用 5 对合成样例时敌意已有 0.84（均值）和 0.92（前 16 个 token）。
- **换对话来源也成立。** 事后把合成样例按对话来源拆开：完全不用敌意数据集的对话时，敌意仍是 0.83 和 0.94。
- **在激活上迁移得比在文字上好。** 合成回复的用词和真实回复不同，文本分类器在愤怒、喜悦上只有 0.74–0.78，激活方向是 0.98–1.00。
- **附和不成立。** 0.53–0.58，接近随机。只用附和数据集的对话来生成也一样（0.55–0.57）。按指令"顺着用户说"写出的回复，和模型真正附和时的内部状态不是一回事。

### 2. 逐 token 读数

把每个 token 的状态投影到正常语料的前 128 个主成分上保存，再比较三种汇总方式。

| 概念 | 样例数 | 全部 token 取均值 | 取最大值 | 最高 5 个 token 的均值 |
|---|---|---|---|---|
| 敌意 | 5 | 0.94 | 0.93 | 0.96 |
| 敌意 | 全部 | 0.94 | 0.94 | **0.98** |
| 附和 | 全部 | 0.75 | 0.62 | 0.63 |
| 用户困扰 | 全部 | 0.99 | 0.98 | 0.98 |

敌意上"最高 5 个 token"比均值高 0.01–0.03，其他概念没有提升，附和反而变差。提升有限：敌意验证集只有 12 个阳性样本，这个差距在噪声范围内。

### 3. 正常语料的规模

少样例方向，敌意，回复均值，第 18 层。括号里是第二轮（只有原来三种场景的 1045 条）。

| 正常样本数 | k=1 | k=5 | k=20 | 全部样例 |
|---|---|---|---|---|
| （第二轮）1045 | 0.84 | 0.89 | 0.89 | 0.90 |
| 500 | 0.82 | 0.90 | 0.92 | 0.92 |
| 1000 | 0.80 | 0.90 | 0.93 | 0.93 |
| 2500 | 0.83 | 0.92 | 0.94 | 0.95 |
| 4924 | 0.83 | 0.92 | 0.94 | 0.95 |

- 更广的正常语料把敌意从 0.90 提到 0.95，和有监督探针持平。2500 条之后不再增长。
- 起作用的主要是多样性：混入新场景的 500 条就比原来单一场景的 1045 条好。
- 回复之前的读数没有变化（敌意 0.87，附和 0.75）。附和在回复均值上也没有变化（0.76）。

### 这一轮的结论

1. 对敌意和情绪语气，**新概念可以只靠一句话定义**，不需要收集真实样例。
2. 附和是另一类问题：它不是一种语气，合成样例、逐 token 读数、更大的正常语料都没有帮助。
3. 同样是探索性结果。合成样例没有经过检查，其中一部分取自本身带有敌意历史的对话，"正常"的那一半也可能带敌意。按对话来源拆分是事后做的。

汇总指标：[`contrast`](results/contrast_val_qwen3-4b.json)、[`tokens`](results/tokens_val_qwen3-4b.json)、`results/fewshot_val_qwen3-4b_normal*.json`。

## 方法

### 读哪里的激活

对每条记录，用模型自己的对话模板拼出提示，再让模型读一遍目标文本（不生成）。在五个相对深度（0.25 / 0.4 / 0.5 / 0.6 / 0.75）取残差流激活，每层保存三种读数：

| 读数 | 位置 | 用途 |
|---|---|---|
| `pre` | 提示的最后一个位置 | 模型开口之前的状态，用于提前预警 |
| `early` | 回复前 16 个 token 的均值 | 刚开口时 |
| `mean` | 整段目标文本的均值 | 事后判断 |

层按相对深度选，不写死层号，所以换模型只需要改模型名。

### 检测器

| 检测器 | 做法 |
|---|---|
| Mahalanobis | 到正常样本云的距离：主成分内的白化距离，加上主成分之外的残差 |
| 去内容 Mahalanobis | 先去掉正常数据中随话题变化的方向，再算距离 |
| kNN | 到最近的 k 个正常样本的平均距离 |
| Isolation Forest | 标准的孤立森林 |
| 自编码器 | 小型瓶颈网络的重构误差 |
| 概念子空间 | 把异常分数拆成两部分：已知风险方向之内，和之外 |
| 少样例方向 | 正常语料提供白化空间，k 个阳性样例的均值减正常均值作为方向 |
| 线性探针（有监督） | 标准化后做逻辑回归，二分类或多分类 |

### 为什么要"去内容"

在这类模型里，对话内容解释了激活的大部分方差，语气和情绪只占很小一部分。直接在原始空间做异常检测，报出来的主要是"话题新"，而不是"行为有风险"。

合成数据上的效果（[`tests/test_detectors.py`](tests/test_detectors.py)）：

| | 普通 Mahalanobis | 去内容 Mahalanobis |
|---|---|---|
| 没见过的风险偏移（越高越好） | 0.995 | 0.996 |
| 远离训练话题的新话题（越接近 0.5 越好） | 1.000 | 0.63 |

内容方向是从数据里估计的，所以误报能大幅降低，但做不到完全消除。在第一轮真实数据上，这一步没有带来可见的收益。

### 评估规则

- 单类检测器只在开发集的正常样本上拟合，从不接触风险样本。
- 同一个模板或场景的样本不会同时出现在两个划分里。
- 置信区间按模板分组做 bootstrap。
- **换话题对照**：留出五分之一的正常模板不参与拟合，用它们的分数定报警阈值；再看新话题的正常样本有多少超过阈值。
- **测试集只开一次**：先在验证集上选层和读数方式，写入冻结文件，再评估测试集。代码会拒绝第二次运行。

## 安装和运行

在 Python 3.12 上测试过。提取激活需要 GPU；检测器和评估在 CPU 上就能跑。

```bash
git clone https://github.com/LookJohnny/nous-anomaly.git
cd nous-anomaly
python -m venv .venv && .venv/bin/pip install -r requirements.txt
.venv/bin/python -m pytest -q        # 29 项；没有数据源时跳过 1 项
```

三步流程：

```bash
# 1. 提取激活。多卡时每张卡跑一个分片；中断后重跑会跳过已完成的部分
python -m nous_anomaly.extract --model Qwen/Qwen3-4B-Instruct-2507 \
    --records data/records.jsonl --out feats/qwen3-4b --shard 0/1

# 可选：每个概念需要几个样例（少样例曲线）
python -m nous_anomaly.evaluate fewshot --records data/records.jsonl \
    --feats feats/qwen3-4b --out out/fewshot_val.json

# 可选：让模型自己写正常对话和对比样例，并入记录后重新提取（同时保存逐 token 状态）
python -m nous_anomaly.generate normal   --model Qwen/Qwen3-4B-Instruct-2507 --out data/gen.jsonl
python -m nous_anomaly.generate contrast --model Qwen/Qwen3-4B-Instruct-2507 \
    --records data/records.jsonl --out data/syn.jsonl
python -m nous_anomaly.evaluate basis --records data/records.jsonl --feats feats/qwen3-4b --out out/basis.npz
#   提取时加 --token-basis out/basis.npz
python -m nous_anomaly.evaluate contrast --records data/records.jsonl --feats feats/qwen3-4b-v2 --out out/contrast_val.json
python -m nous_anomaly.evaluate tokens   --records data/records.jsonl --feats feats/qwen3-4b-v2 --out out/tokens_val.json

# 2. 在验证集上扫描所有层和读数方式
python -m nous_anomaly.evaluate sweep --records data/records.jsonl \
    --feats feats/qwen3-4b --out out/sweep_val.json

# 3. 冻结设置，然后开一次测试集
python -m nous_anomaly.evaluate freeze --sweep out/sweep_val.json --out out/FREEZE.json
python -m nous_anomaly.evaluate test --records data/records.jsonl \
    --feats feats/qwen3-4b --freeze out/FREEZE.json --out out/test.json
```

参考耗时：一张 RTX PRO 6000 上，4160 条记录的提取用了 138 秒；生成 5000 条正常对话和 3000 条对比回复约 25 分钟。

## 数据

**本仓库不包含对话数据和激活特征。** 第一轮实验用的四个数据集来自一个尚未公开的研究仓库；`nous_anomaly/data.py` 里的适配器是为它写的。

用自己的数据时，准备一个 JSONL 文件，每行一条记录：

```json
{
  "id": "mydata:001",
  "source": "mydata",
  "site": "reply",
  "system": "你是客服助手。",
  "messages": [{"role": "user", "content": "我的包裹丢了。"}],
  "target": "非常抱歉，我马上帮您查。",
  "group": "template-17",
  "topic": "客服",
  "split": "dev",
  "labels": {"hostile": 0}
}
```

| 字段 | 含义 |
|---|---|
| `site` | `reply`：读模型回复上的状态。`user`：读最后一条用户消息上的状态，此时 `target` 必须等于那条消息 |
| `group` | 模板或场景编号。同一组不能跨划分 |
| `split` | `dev`、`val` 或 `test` |
| `labels` | `hostile`、`distress`、`syco` 取 0 或 1；`emotion` 取 `anger`、`joy`、`sadness` 或 `neutral` |

没有任何风险标签、情绪为中性或未标的记录，会被当作"正常"样本。

## 代码结构

| 文件 | 内容 |
|---|---|
| [`nous_anomaly/data.py`](nous_anomaly/data.py) | 记录格式、校验、数据集适配器 |
| [`nous_anomaly/extract.py`](nous_anomaly/extract.py) | 从任意 HuggingFace 因果语言模型提取激活，支持分片、断点续跑和逐 token 保存 |
| [`nous_anomaly/generate.py`](nous_anomaly/generate.py) | 让被研究的模型自己写正常对话和成对的对比回复 |
| [`nous_anomaly/detectors.py`](nous_anomaly/detectors.py) | 单类检测器、少样例方向和线性探针 |
| [`nous_anomaly/evaluate.py`](nous_anomaly/evaluate.py) | 指标、bootstrap、换话题对照、冻结和一次性测试 |
| [`tests/`](tests/) | 合成数据上的检测器测试；用随机初始化的微型模型验证取数位置 |
| [`results/`](results/) | 三轮的汇总指标 |

## 局限

- 结果来自一个模型、一种语言、一轮验证集。
- 标签来自 LLM 评分者，没有人工校准。
- 数据集的测试部分在更早的研究中已被使用过，不是全新的封存集。
- 新增的正常语料和对比样例都是模型自己生成的，没有人工检查。
- 第一轮的单类检测器没有在扩大后的正常语料上重跑。
- 只读取了残差流的五个层，没有读注意力头或 MLP 的输出。

## 下一步

- **附和**：需要另一种思路，例如读"模型是否知道用户说错了"和"回复是否纠正"之间的差，而不是找一个语气方向。
- **新的封存测试集和预先登记的通过门槛**，包括"只用合成样例"这一条。
- **更多概念**：用一句话定义试更多风险类型，看哪些像敌意一样成立，哪些像附和一样不成立。
- **已知方向之外的异常**：用概念子空间检测器，把"已有探针能解释的偏离"和"解释不了的偏离"分开。
- **更多模型**：Qwen3-8B、Qwen3-14B、Llama-3.1-8B。
- **人工校准**：对评分者的标签和合成样例做抽检。
