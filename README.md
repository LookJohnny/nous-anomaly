# nous-anomaly

**在大模型的内部激活上做异常检测：模型"状态不对"时，能不能不靠标注就发现？**

这个项目读取开源大模型每一层的内部激活，在上面训练两类检测器，并在同一批数据上正面比较：

- **单类异常检测器**：只见过"正常"对话的激活，偏离就报警。不需要任何风险样本。
- **有监督线性探针**：用标注过的风险样本训练，作为参照上限。

它是 [Nous Agent Safety](https://github.com/LookJohnny/nous-agent-safety) 的研究组件，对应其中"读取模型内部状态来监测风险"的方向。

> 状态：研究原型。目前只在一个模型（Qwen3-4B）的验证集上跑过一轮，测试集没有开封。所有标签来自 LLM 评分者，没有人工校准。

## 第一轮结果

模型 Qwen3-4B-Instruct-2507，4160 条中文对话记录，验证集，2026-11-18。数字是 AUROC（0.5 相当于随机猜）。

**结论：纯单类异常检测能发现情绪语气的变化，但发现不了敌意和附和。**

| 要检测的概念 | 单类检测器（没见过任何阳性样本） | 有监督线性探针 | 文本分类器 |
|---|---|---|---|
| 愤怒 / 喜悦 / 悲伤的语气 | **0.99** | 1.00 | 1.00 |
| 用户困扰（含明显关键词） | 0.67–0.80 | 0.997 | 0.994 |
| 用户困扰（去掉关键词） | 0.44–0.65 | 未测 | 未测 |
| 模型对用户的敌意 | 多数设置 0.43–0.77 | 0.94–0.97 | 0.94 |
| 附和（顺着用户的错误说法） | 0.32–0.53 | 0.87 | 0.71 |

怎么读这张表：

1. **情绪语气在中层最容易被发现。** 单类检测器在模型深度一半的位置（36 层中的第 18 层）达到 0.99，往浅层和深层都下降。不过这批数据里，带情绪的回复有一句明确的情绪开头，文本分类器也是 1.00。所以这一行只说明"语气明显变了能被发现"。
2. **敌意和附和不是离群点。** 敌意回复在激活空间里并不比正常回复离得更远。附和回复甚至比正常回复更"典型"，分数低于 0.5。只用同一数据集的正常样本来拟合，也没有改善。
3. **原因是高维稀释。** 风险信号只是少数几个方向上的偏移，淹没在其余两千多维的正常波动里。单类检测器不知道该看哪个方向。
4. **有监督探针有效。** 同一批激活上，线性探针检测敌意达到 0.94–0.97。在附和上，它比只看文字的分类器高 0.16，而且在模型开口之前就能读出来。
5. **"去内容"处理在真实数据上几乎没有额外收益。** 它和普通 Mahalanobis 的差别在 0.01 以内。换话题造成的误报本来就不高：没见过的话题上，正常对话的误报率是 3–11%，目标值是 5%。

这对方向的含义：要检测敌意、附和这类风险，仍然需要标注或对比数据来指明方向。纯单类检测可以留作"语气明显异常"的兜底信号。

### 读结果时要注意

- **验证集很小。** 敌意只有 12 个阳性样本，所有数字都是探索性的。
- **敌意一行的上限不可靠。** 个别设置能到 0.87，但那是 60 个设置里的最大值，不能当作结果。
- **有一次偏离预定流程。** 探索"按数据来源单独拟合"时，去关键词的困扰数据用了划给测试集的那部分，没有经过冻结。那一行只能算探索性数字。其余数据集的测试集没有开封。
- **只有一个模型、一种语言。** Qwen3-4B，中文。

原始数字在 [`results/`](results/)，只含汇总指标，不含对话原文。

## 方法

### 读哪里的激活

对每条记录，用模型自己的对话模板拼出提示，再让模型读一遍目标文本（不生成）。在五个相对深度（0.25 / 0.4 / 0.5 / 0.6 / 0.75）取残差流激活，每层保存三种读数：

| 读数 | 位置 | 用途 |
|---|---|---|
| `pre` | 提示的最后一个位置 | 模型开口之前的状态，用于提前预警 |
| `early` | 回复前 16 个 token 的均值 | 刚开口时 |
| `mean` | 整段目标文本的均值 | 事后判断 |

层按相对深度选，不写死层号，所以换模型只需要改模型名。

### 检测器

| 检测器 | 做法 |
|---|---|
| Mahalanobis | 到正常样本云的距离：主成分内的白化距离，加上主成分之外的残差 |
| 去内容 Mahalanobis | 先去掉正常数据中随话题变化的方向，再算距离 |
| kNN | 到最近的 k 个正常样本的平均距离 |
| Isolation Forest | 标准的孤立森林 |
| 自编码器 | 小型瓶颈网络的重构误差 |
| 概念子空间 | 把异常分数拆成两部分：已知风险方向之内，和之外 |
| 线性探针（有监督） | 标准化后做逻辑回归，二分类或多分类 |

### 为什么要"去内容"

在这类模型里，对话内容解释了激活的大部分方差，语气和情绪只占很小一部分。直接在原始空间做异常检测，报出来的主要是"话题新"，而不是"行为有风险"。

合成数据上的效果（[`tests/test_detectors.py`](tests/test_detectors.py)）：

| | 普通 Mahalanobis | 去内容 Mahalanobis |
|---|---|---|
| 没见过的风险偏移（越高越好） | 0.995 | 0.996 |
| 远离训练话题的新话题（越接近 0.5 越好） | 1.000 | 0.63 |

内容方向是从数据里估计的，所以误报能大幅降低，但做不到完全消除。在第一轮真实数据上，这一步没有带来可见的收益。

### 评估规则

- 单类检测器只在开发集的正常样本上拟合，从不接触风险样本。
- 同一个模板或场景的样本不会同时出现在两个划分里。
- 置信区间按模板分组做 bootstrap。
- **换话题对照**：留出五分之一的正常模板不参与拟合，用它们的分数定报警阈值；再看新话题的正常样本有多少超过阈值。
- **测试集只开一次**：先在验证集上选层和读数方式，写入冻结文件，再评估测试集。代码会拒绝第二次运行。

## 安装和运行

在 Python 3.12 上测试过。提取激活需要 GPU；检测器和评估在 CPU 上就能跑。

```bash
git clone https://github.com/LookJohnny/nous-anomaly.git
cd nous-anomaly
python -m venv .venv && .venv/bin/pip install -r requirements.txt
.venv/bin/python -m pytest -q        # 22 项；没有数据源时跳过 1 项
```

三步流程：

```bash
# 1. 提取激活。多卡时每张卡跑一个分片；中断后重跑会跳过已完成的部分
python -m nous_anomaly.extract --model Qwen/Qwen3-4B-Instruct-2507 \
    --records data/records.jsonl --out feats/qwen3-4b --shard 0/1

# 2. 在验证集上扫描所有层和读数方式
python -m nous_anomaly.evaluate sweep --records data/records.jsonl \
    --feats feats/qwen3-4b --out out/sweep_val.json

# 3. 冻结设置，然后开一次测试集
python -m nous_anomaly.evaluate freeze --sweep out/sweep_val.json --out out/FREEZE.json
python -m nous_anomaly.evaluate test --records data/records.jsonl \
    --feats feats/qwen3-4b --freeze out/FREEZE.json --out out/test.json
```

参考耗时：一张 RTX PRO 6000 上，4160 条记录的提取用了 138 秒。

## 数据

**本仓库不包含对话数据和激活特征。** 第一轮实验用的四个数据集来自一个尚未公开的研究仓库；`nous_anomaly/data.py` 里的适配器是为它写的。

用自己的数据时，准备一个 JSONL 文件，每行一条记录：

```json
{
  "id": "mydata:001",
  "source": "mydata",
  "site": "reply",
  "system": "你是客服助手。",
  "messages": [{"role": "user", "content": "我的包裹丢了。"}],
  "target": "非常抱歉，我马上帮您查。",
  "group": "template-17",
  "topic": "客服",
  "split": "dev",
  "labels": {"hostile": 0}
}
```

| 字段 | 含义 |
|---|---|
| `site` | `reply`：读模型回复上的状态。`user`：读最后一条用户消息上的状态，此时 `target` 必须等于那条消息 |
| `group` | 模板或场景编号。同一组不能跨划分 |
| `split` | `dev`、`val` 或 `test` |
| `labels` | `hostile`、`distress`、`syco` 取 0 或 1；`emotion` 取 `anger`、`joy`、`sadness` 或 `neutral` |

没有任何风险标签、情绪为中性或未标的记录，会被当作"正常"样本。

## 代码结构

| 文件 | 内容 |
|---|---|
| [`nous_anomaly/data.py`](nous_anomaly/data.py) | 记录格式、校验、数据集适配器 |
| [`nous_anomaly/extract.py`](nous_anomaly/extract.py) | 从任意 HuggingFace 因果语言模型提取激活，支持分片和断点续跑 |
| [`nous_anomaly/detectors.py`](nous_anomaly/detectors.py) | 六种单类检测器和线性探针 |
| [`nous_anomaly/evaluate.py`](nous_anomaly/evaluate.py) | 指标、bootstrap、换话题对照、冻结和一次性测试 |
| [`tests/`](tests/) | 合成数据上的检测器测试；用随机初始化的微型模型验证取数位置 |
| [`results/`](results/) | 第一轮的汇总指标 |

## 局限

- 结果来自一个模型、一种语言、一轮验证集。
- 标签来自 LLM 评分者，没有人工校准。
- 数据集的测试部分在更早的研究中已被使用过，不是全新的封存集。
- 正常样本只有一千多条，而且来自少数几种对话场景。更大、更多样的正常语料可能改变单类检测器的表现，目前没有验证。
- 只读取了残差流的五个层，没有读注意力头或 MLP 的输出。

## 下一步

- **半监督检测**：给检测器少量已知风险样本，看需要多少才能接近有监督探针。
- **已知方向之外的异常**：用概念子空间检测器，把"已有探针能解释的偏离"和"解释不了的偏离"分开。
- **更大的正常语料**：扩到五千条以上，覆盖更多场景和英文。
- **更多模型**：Qwen3-8B、Qwen3-14B、Llama-3.1-8B。
- **人工校准**：对评分者的标签做抽检。
